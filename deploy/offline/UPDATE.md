# LiftControl 0.13.16 — PWA и GitHub-обновления

Сначала установите обновление на стенде. APK 0.13.14 остаётся совместимым, новые сборки не выпускаются. После проверки можно один раз включить автоматическое скачивание подписанных стабильных релизов. См. документацию GITHUB_UPDATES.md в пакете. 

## Установка панели

В папке, куда загружен архив:

```bash
unzip LiftControl-v0.13.16-update.zip
cd LiftControl-v0.13.16-update
sha256sum --check --strict PATCH.sha256
sudo bash update-panel.sh
```

Установщик рассчитан на действующие установки 0.8–0.11, 0.11.1, 0.12.0, 0.13.0, 0.13.1, 0.13.2, 0.13.3, 0.13.4, 0.13.5, 0.13.6, 0.13.7, 0.13.8, 0.13.9, 0.13.10, 0.13.11, 0.13.12, 0.13.13, 0.13.14, 0.13.15 и повторный запуск 0.13.16. Нужен Docker Compose и свободное место для миграции и копии. Установщик использует прежний образ и включает подготовленный Python-пакет для PDF и шрифт с лицензией. На VPS загрузка зависимостей не требуется.

Перед переходом сохраняются прежний образ и база. На время переноса API и отправщики уведомлений останавливаются. Всё старое хранилище, включая документы, копируется с проверкой SHA-256. Совпадающие файлы пропускаются при повторном запуске; конфликтующие не перезаписываются. Старый Docker-том не удаляется.

После миграций старые вложения заявок, чатов и заданий регистрируются в медиатеке. Их прежние пути остаются в базе для совместимости и отката. При отсутствующем или повреждённом файле переход останавливается; подробности находятся в `media-migration.log` в созданной папке `/opt/liftcontrol/backups/before-offline-ДАТА/`. Возвращается прежний образ. Устранив причину, повторите установку.

Установщик запускает миграции Django, проверяет API 0.13.16 и создаёт полный архив. Новые записи и файлы после запуска находятся в действующей базе и хранилище. При откате работающей системы сначала сохраните её актуальный архив.

Для создания одноразовых ссылок на установку пароля используйте HTTPS-адрес панели, который открывается у сотрудника. В панели выберите «Настройки → Добавить сотрудника» и скопируйте ссылку. Сотрудник может установить пароль в браузере в течение 24 часов. Для действующей учётной записи доступ в другую организацию выдаётся по коду приглашения.

Штатный HTTPS-прокси применяет новый предел автоматически. Для собственного NGINX установите `client_max_body_size 501m;` в области `/api/`, чтобы запрос мог содержать до пяти файлов и служебные поля multipart. Временные файлы API пишутся в `/srv/liftcontrol-data/upload-tmp`.

## Хранилище

Постоянный каталог оригиналов и миниатюр:

```text
/srv/liftcontrol-data/media/
```

Новые медиа имеют структуру `org_ID/ГОД/МЕСЯЦ/UUID/original.ext` и `preview.webp`. Оригинал — файл, принятый сервером после сжатия на телефоне или в браузере. Дополнительного уменьшения оригинала сервер не делает. Для видео создаётся кадр миниатюры, если декодер доступен; автоматического перекодирования видео в этой версии нет.

Один и тот же файл внутри организации хранится один раз; связи с заявкой, лифтом, чатом и заданием не создают копий. Между организациями файлы изолированы. Первоначальный автор и дата загрузки сохраняются. Связи имеют категории «Неисправность», «Ход работ», «Результат ремонта», «Прочее».

Каталог доступен в панели через «Медиаматериалы», в приложении — «Боковое меню → Медиаматериалы». В лифте, заявке и чате есть кнопки вложений. Поддерживаются фильтры адреса, лифта, заявки, автора, периода и типа. В чате материалы сгруппированы по месяцам, в карточке лифта — по заявкам. Из файла можно открыть исходное сообщение или связать его с заявкой/лифтом при наличии прав.

Файлы открываются только через авторизованный API. Каталог нельзя публиковать через NGINX. Техническая документация остаётся в своей библиотеке с автоматическим подбором. Физическое удаление материалов и автоматическое удаление по сроку не включены. Старые копии совместимости пока занимают дополнительное место; счётчик медиатеки показывает оригиналы и миниатюры новых записей, без резервных архивов и старого тома.

## Телефон без интернета

Фото и видео из чата, медиатеки и фотоотчёта задания сохраняются в закрытой памяти приложения, отдельно от временного кэша. Файлы шифруются AES-GCM с ключом Android Keystore; метаданные и очередь — в локальной базе. Фото заявки продолжают использовать зашифрованную очередь отчётов.

Надпись «Сохранено на телефоне» появляется после записи файла и очереди. Перезапуск, очистка кэша внутри приложения и выход из аккаунта не удаляют очередь. После входа тем же аккаунтом в ту же организацию отправка продолжится. При переназначении задания сервер повторно проверит права; отклонённый файл останется на телефоне с причиной в очереди.

Каждая загрузка имеет постоянный UUID: повтор после обрыва связи не дублирует сообщение или файл. «На сервере» означает, что сервер сохранил файл и связь. После этого локальная копия удаляется. Общий предел ожидающих файлов — 550 МБ. Один файл может занимать до 100 МБ (104 857 600 байт). В сообщении допускается до пяти вложений. Видео длится до трёх минут. Полная очистка данных Android, удаление приложения и потеря телефона уничтожат ещё не отправленные материалы.

## Резервные копии и восстановление

Полный архив базы и медиа создаётся при обновлении и ежедневно около 03:30 по Чите, если сервер использует systemd. Отдельный таймер оставляет прежнее задание резервирования базы и ролей PostgreSQL. Во время ежедневного копирования приложение продолжает работать. Скрипт снимает дамп через `pg_dump`, копирует неизменяемые опубликованные файлы и проверяет размер и SHA-256 каждого элемента архива. Список объектов дампа проверяется через `pg_restore`.

```bash
sudo python3 /opt/liftcontrol/backup-media.py
sudo systemctl status liftcontrol-media-backup.timer
sudo journalctl -u liftcontrol-media-backup.service -n 30 --no-pager
```

Архивы находятся в `/srv/liftcontrol-data/backups/`. Проверка отдельного архива:

```bash
sudo python3 /opt/liftcontrol/backup-media.py --verify /srv/liftcontrol-data/backups/ИМЯ-АРХИВА.tar.gz
```

Удаление старых архивов пока не настроено. Если для следующей копии не остаётся расчётного объёма и резерва 1 ГБ, задание остановится с `BACKUP_SPACE_LOW`, сохранив существующие файлы и архивы.

Для копии вне VPS от администратора глобально требуется выбрать отдельный SSH-сервер/хранилище, доступ и срок хранения. Пока назначения нет, выводится `OFFSITE_NOT_CONFIGURED`: локальная копия не защищает от потери всего VPS. После настройки SSH-ключа и проверки ключа удалённого сервера укажите в `/opt/liftcontrol/backup-remote.txt` строку `user@host:/absolute/path`. Скрипт отправит архив через SCP и сверит SHA-256 на удалённом сервере. Ключи, каталоги и существование назначения автоматически не создаются.

Восстановление выполняйте сначала на отдельном сервере: остановите API/отправщики, проверьте архив, извлеките его в закрытую временную папку, восстановите `database.dump` через `pg_restore` в чистую базу с теми же ролями и схемой `app`, а содержимое `media/` — в `/srv/liftcontrol-data/media` с владельцем UID/GID 10001. Запустите ту же версию приложения и проверьте вход, заявки и открытие нескольких фото/видео. Прежде чем считать резервирование рабочим, нужен такой пробный запуск; автоматическая проверка архива не заменяет его.

## Обновление APK и логи

Поместите готовый APK в:

```text
/opt/liftcontrol/updates/android/
```

Стандартная установка панели создаёт папку. В Server Box откройте её по полному пути. Загружайте готовый подписанный APK сначала с окончанием `.part`, после завершения переименуйте в `.apk`. Сервер читает версию из файла, поэтому имя может быть любым. Для метаданных сборки и примечаний доступен `publish-android.sh` из пакета выпуска APK.

При открытии приложение сравнит версию на сервере со своей. Окно появляется только для более новой сборки. Установку подтверждает Android. Push о новом APK дополнительно требует настроенного FCM и приложения с поддержкой этого уведомления.

Фото перед отправкой уменьшаются на клиенте. Beta-логи включены: сохранение, повторная отправка и ошибки чтения отмечаются без содержимого файлов, паролей и токенов. Push по-прежнему требует настроенного Firebase на сервере; система хранения от Firebase не зависит.

## Проверка карточки лифта

После установки обновите страницу и проверьте номер Web 0.13.16. Загрузите PDF ровно 100 МБ в «Документацию» и откройте его. Файл на один байт больше должен быть отклонён. Повторите проверку в Android с правами администратора и проверьте отправку видео в чат.

## Проверка новых действий

- Создайте заявку на один лифт с назначенным механиком. На телефоне механика установите Android 0.13.14. Проверьте статус доставки при открытом приложении и с включённым FCM, а затем попробуйте с выключенным телефоном. Через пять минут отправителю приходит предупреждение об отсутствии подтверждения. Отметка о доставке не меняет статус заявки.
- В общей «Документации» укажите несколько тегов через запятую. Такой PDF появляется у лифта, в карточке которого есть все эти теги. Без тегов действуют производитель и модель.
- Проверьте, что расход видит администратор, а возмещение получает автор. Уведомления доступны во вкладке «Пусконаладка».
- В Android откройте «Аналитика → Дежурство» и сверьте завершённые смены и принятые подмены за выбранный период.

## Проверка журнала ТО

Откройте «Объекты», выберите лифт и вкладку «Журнал ТО». Скачайте PDF за период, в котором есть выполненное ТО и закрытая заявка. Сверьте дату фактического выполнения, работы и исполнителя. Планирование и закрытие работ по ТО доступны на вкладке «План ТО». После установки на тестовый телефон проверьте этот же путь в Android.

## Проверка пусконаладки

Из аккаунта исполнителя отправьте сообщение и комментарий о ходе работ с фото. Сверьте вложения и уведомления с аккаунта руководителя и исполнителя, назначенного на лифт. В Android системные уведомления требуют действующей настройки FCM и разрешения на уведомления. Для отправки фотографий в Android нужна связь с сервером.

## Тихие часы и личные push

В Android и веб-панели откройте «Настройки → Настройки push». Выберите ежедневный тихий интервал, дни без push или режим «Только мои push». Время берётся из часового пояса организации. Во время паузы сервер пропускает системные уведомления, а доступные события остаются в центре уведомлений.

## Документы и освидетельствование

В разделе «Документы» администратор выбирает лифт и подраздел «Договоры», «Приказы о назначении» или «Освидетельствование». Из этого раздела можно загрузить либо удалить PDF. Акты опубликованы для просмотра во вкладке «Освидетельствование» в карточке лифта.

В подразделе «Освидетельствование» администратор вручную назначает дату. За 5 дней до неё ответственный механик получает по одному напоминанию в день с адресом и датой. Отсчёт начинается в 09:00 по часовому поясу организации. Если дата изменится, напоминания по прежней дате исчезнут из центра уведомлений. Для системных уведомлений нужен настроенный Firebase и разрешение Android.

Центр уведомлений показывает обычные события и заявки с застреваниями в разных вкладках. Колокольчик показывает суммарное количество непрочитанных.
