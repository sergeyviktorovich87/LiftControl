# LiftControl Infrastructure Installer (v0.1)

Базовый установщик LiftControl **только для нового Ubuntu 24.04 LTS VPS**. На уже работающем сервере выполнять **audit.sh**, а не install.sh. Существующие `compose.yaml`, базы и SSH-ключи установщик не перезаписывает: при обнаружении работающей установки он откажется запускаться.

## Состав

- `install.sh`: предустановочные проверки, официальный Docker CE + Compose, базовая настройка SSH/UFW (после проверки authorized_keys), обновления безопасности, 2 ГБ swap на маленьком VPS, journald, PostgreSQL 18 без публикации порта, секреты в `/opt/liftcontrol/secrets`, `liftapp` и `liftmigrator`, ежедневные дампы БД + глобальных ролей, ежечасный локальный healthcheck.
- `audit.sh`: чтение статуса установленного сервера **без изменений**.
- `backup-db.sh`: `pg_dump` в формате custom + `pg_dumpall --globals-only` с проверкой архивов. Старые копии **не удаляет**.
- `healthcheck.sh`: журналируемые проверки PostgreSQL, свободного места и свежести обеих копий.

## Безопасность и границы

1. Установщик предназначен для **новой** машины. Требует запуск через `sudo` от существующего пользователя с `authorized_keys`, рабочим sudo и отдельным проверенным SSH-ключом.
2. Сначала проверьте, что авторизация по ключу работает в **новой** SSH-сессии, только затем полагайтесь на блокировку парольного входа. Изменения портов, провайдерского firewall и cloud-init требуют отдельной проверки.
3. Никаких открытых портов БД. Docker-порты способны обходить некоторые правила UFW; перед публикацией любых приложений нужно отдельно проектировать сетевой доступ.
4. Секреты никогда не коммитить в Git, не присылать в чат и не класть в обычные логи. `postgres_admin_password`, `postgres_app_password`, `postgres_migrator_password` создаются локально на VPS. Приложения добавляются отдельно.
5. Локальные дампы и журналы **не заменяют** независимых резервных копий. Для временного тестового этапа сохраняйте зашифрованную копию на ПК и телефон. Для производства нужны автоматические внешние копии и проверенная процедура восстановления.
6. Локальные healthcheck-логи — **не удалённые уведомления**. Если VPS полностью недоступен, локальная проверка не сообщит об этом. Нужен отдельный внешний мониторинг.
7. Этот установщик **не** разворачивает Django, React, Flutter, другие панели, SMTP, HTTPS либо сам по себе не доказывает готовность к обработке рабочих данных. Подключение дополнительных сервисов делайте изолированными Docker Compose-стеками с отдельными базами и правами.

## Проверить существующий сервер

При наличии файла на сервере:

```bash
sudo bash audit.sh
```

Проверки не читают и не выводят парольную информацию.

## Установить на новый сервер

Подготовьте новый Ubuntu 24.04, пользователя с `sudo`, SSH-ключ и четыре файла этого каталога. Не пересылайте приватный SSH-ключ вместе с файлами установщика.

```bash
sudo bash install.sh
sudo /opt/liftcontrol/scripts/audit.sh
sudo systemctl status liftcontrol-backup.timer --no-pager
sudo systemctl status liftcontrol-healthcheck.timer --no-pager
sudo journalctl -u liftcontrol-healthcheck.service -n 50 --no-pager
```

Если любой пункт проверки показал WARN — устраните причину, прежде чем загружать реальные данные.

## Восстановление

Резервные копии в `/opt/liftcontrol/backups`: два файла `liftcontrol-*.dump` и `postgres-globals-*.sql` одного запуска. Глобальные роли содержат чувствительную информацию (хеши паролей). Храните их только в зашифрованном виде при переносе с VPS.

Не запускайте восстановление поверх рабочей базы без отдельной проверенной инструкции, снимка состояния и окна обслуживания. Восстановление из базы и ролей нужно дополнить файлами приложения, секретами и пользовательскими загрузками. **Автоматический restore в версии 0.1 не реализован и не испытан.**

## Дальнейшее развитие

- Модули `liftcontrol-api`, `web`, `reverse-proxy`, `vpn-panel`, `file-storage` — отдельно от базовой инфраструктуры; не объединять сервисы общим PostgreSQL-суперпользователем.
- Ansible-роли для развёртывания с управляющего компьютера, обновлений и миграций с откатом.
- Внешний объектный backup через Restic, тесты восстановления и защита копий от удаления.
- Внешние уведомления/проверка доступности и TLS при публикации API.
