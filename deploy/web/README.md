# LiftControl Web 0.1 — закрытый тестовый интерфейс

Существующая React/Vite панель `web/` теперь выводит реальные данные из Django API. Для авторизации использует **существующую Django session cookie**: отдельные токены в браузере или localStorage не хранятся. Редактирование пока выполняется через ссылки Django Admin.

## Безопасность и доступ

- Домашний маршрут `/` доступен только пользователям `is_staff=True`; без входа перенаправляет на `/admin/login/?next=/`.
- API возвращает данные только сотрудникам с `is_staff=True` (`IsAdminUser` DRF). Ограничения по отдельным объектам пока нет.
- Публичный вход запрещён; VPS слушает только `127.0.0.1:18080` через SSH-туннель.
- Все запросы React обращаются к `/api/...` по тому же origin, CORS и токены не нужны.
- Журнал тестовой версии показывает время, endpoint и HTTP-код/тип ошибки; пароль, токены и содержимое заявок в него не записываются.
- Это не окончательная модель прав доступа. До доступа механиков и диспетчеров необходимо внедрить полноценные роли и ограничения по объектам.
- Отдельный запрет на каскадное удаление объектов/лифтов с историей работ ещё не реализован.

## Сборка образа без Docker Hub на VPS

В GitHub Actions workflow `Build downloadable LiftControl API image`:
1. `npm install` и `npm run build -- --base=/static/web/` в `web/`.
2. Копирует `dist/index.html` в `backend/templates/index.html`.
3. Копирует `dist/assets/` в `backend/static/web/assets/`.
4. Выполняет Docker build `backend/` + `collectstatic`, сохраняет образ `liftcontrol-api:pilot` в `tar.gz`.
5. Загружает приватный GitHub artifact с контрольной суммой SHA-256.

На VPS импорт нового образа `docker load`, затем пересоздание **только** контейнера `api` командой с `--no-deps --no-build --pull never --force-recreate` (команды развёртывания выдаются отдельно после проверки артефакта).
PostgreSQL и существующие Docker secrets не изменяются, миграции для этого обновления не требуются.

## Как проверить

Через SSH-туннель:
- `http://127.0.0.1:18080/` — React-панель, если вошёл администратор.
- `http://127.0.0.1:18080/admin/` — Django Admin.
- `http://127.0.0.1:18080/api/health/` — публичная проверка здоровья (только loopback).
- `/api/buildings/`, `/api/tickets/` — должны возвращать 401/403 без авторизации.

При ошибках см. `docker compose -f compose.yaml -f compose.api.yaml logs --tail=100 api`.
Для тестового UI можно открыть «Журнал тестовой версии» и скопировать обезличенный отчёт.
