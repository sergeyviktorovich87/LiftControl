# LiftControl: HTTPS по IP и системные push

Дополнение к версии 0.6. Работает на существующем VPS `89.169.20.154`; домен покупать сейчас не нужно. Сотрудники смогут открывать приложение по `https://89.169.20.154/` без SSH-туннеля. Будущий домен можно подключить отдельно.

Let’s Encrypt выдаёт доверенные IP-сертификаты через профиль `shortlived`. Они действуют 160 часов, поэтому скрипт устанавливает таймер проверки продления каждые шесть часов. Источники: https://letsencrypt.org/2026/03/11/shorter-certs-certbot/ и https://eff-certbot.readthedocs.io/en/stable/man/certbot.html .

## Один запуск для обновления и доступа с телефона

Скачайте новый полный архив **LiftControl-v0.6-amd64** из успешной сборки ветки `feature/organizations-duty-v06`. Распакуйте его в `/home/liftadmin/update-v06/` и выполните в ServerBox:

```bash
sudo bash /home/liftadmin/update-v06/install-v06-with-https.sh 89.169.20.154
```

Первый этап применяет `update-v06.sh`: сохраняет PostgreSQL/вложения, импортирует 157 единиц Мегаполиса с сохранением аккаунтов. Однократный маркер защищает новые рабочие записи при повторном запуске.

Второй этап получает сертификат, включает HTTPS и запускает отправитель push. База во втором этапе не мигрируется и не очищается. Если сертификат не удалось получить, версия 0.6 и импорт остаются доступны через прежний SSH-туннель. Причина сохраняется в `/opt/liftcontrol/public/setup.log`.

Если 0.6 уже установлена, достаточно:

```bash
sudo bash /home/liftadmin/update-v06/setup-public.sh 89.169.20.154
```

Можно указать уже принадлежащий вам домен вместо IP. До запуска его DNS-запись должна указывать на этот VPS. Дополнительный необязательный параметр `--email адрес@почта.ру` задаёт почту для ACME-аккаунта. При отсутствии почты сертификат выдаётся без неё; уведомления об ошибках продления доступны в журнале сервиса.

## Что делает настройка

- Проверяет, что приложение действительно обновлено до 0.6 и миграции применены.
- Не заменяет чужой веб-сервер: при занятых портах 80/443 останавливается до изменений.
- Сначала поднимает только выдачу ACME-проверок; остальные HTTP-запросы получают 503 до готовности сертификата.
- Проверяет выдачу в тестовой среде Let’s Encrypt с `--dry-run`, затем запрашивает настоящий сертификат. Тестовый сертификат в публичный интерфейс не устанавливается.
- Публикует только HTTP 80 (проверка сертификата и перенаправление) и HTTPS 443. PostgreSQL и внутренний API сохраняют прежние ограничения.
- Запускает NGINX от UID 101 с файловой системой только для чтения и без Linux capabilities. Закрытый TLS-ключ выдаётся только этому процессу с правами 0400.
- Включает Secure cookies Django, проверку адреса, защищённую передачу схемы HTTPS и ограничение попыток входа. Администратор входит под существующим логином; общедоступной регистрации нет.
- Генерирует закрытый VAPID-ключ на VPS либо проверяет и повторно использует существующий. Перезапуск сохраняет подписки телефонов. Закрытые ключи не выводятся в терминал.
- Настраивает продление и перезагрузку сертификата без очистки данных приложения.

Скрипт использует официальные образы NGINX unprivileged и Certbot. Они загружаются Docker на VPS; серверу нужен исходящий интернет. На сетевом экране провайдера должны быть доступны входящие TCP 80 и 443. Если проверка владения адресом завершилась тайм-аутом, проверьте эти правила. SSH 22 и настройки других серверов не изменяются.

## После установки — действия Сергея

1. Открыть `https://89.169.20.154/` на телефоне и войти существующим аккаунтом.
2. Администратором выбрать Мегаполис, связать реальные аккаунты механиков с карточками через приглашения и заполнить график с 09:00.
3. На каждом телефоне открыть Настройки → Включить push; дать браузеру разрешение. Для привычного запуска можно добавить сайт на главный экран.
4. Нажать «Проверить системное уведомление», затем создать настоящую тестовую заявку и свернуть браузер. Первый тест проверяет телефон; заявка — всю цепочку доставки с сервера.
5. Если уведомление отображается без звука, включить звук категории уведомлений браузера в Android и проверить режим «Не беспокоить». Веб-приложение не переопределяет настройки ОС.
6. Постепенно уточнить адреса и заполнить заводские номера, подъезды и реальные остановки по паспортам.

## Проверка и возврат к SSH

Проверка не меняет базу и не выводит ключи/пароли:

```bash
sudo bash /opt/liftcontrol/public/status-public.sh
```

Она показывает адрес, срок сертификата, состояние таймера, отправитель push и количество лифтов по организациям. При успехе первоначального импорта должно быть 157 единиц в Мегаполисе.

Принудительно проверить обычное продление:

```bash
sudo bash /opt/liftcontrol/public/renew-public.sh
```

Отключить публичный доступ, сохранив данные, ключи и прежний SSH-туннель:

```bash
sudo bash /opt/liftcontrol/public/rollback-public.sh
```

Повторная настройка того же адреса поддерживается. Перед сменой IP на домен отключите прежнюю публичную конфигурацию и запустите `setup-public.sh` с новым адресом. При смене адреса на телефонах потребуется новый вход и новая подписка браузера на push; аккаунты и данные приложения сохраняются.

## Проверки перед выпуском

- Отдельные тесты адресов, конфигурации HTTPS, защиты ключа, занятых портов и повторного включения.
- Docker: настоящий NGINX → Django по TLS с отдельным временным тестовым центром сертификации; вход, Secure cookies, CSRF, блокировка чужого Host/Origin, ACME-путь, перезагрузка.
- Существующие проверки версии 0.6: 49 тестов на SQLite и PostgreSQL, компьютер/телефон, сборка и сохранность приватных файлов.

Настоящий сертификат для VPS получается только при запуске на нём. Среда разработки не имеет прямого SSH-доступа к VPS и не изменяет рабочую базу сама.
