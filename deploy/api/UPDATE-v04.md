# LiftControl 0.4 — закрытая тестовая версия

Продолжение существующего проекта Django. Перед установкой можно проверить интерфейс по прежней ссылке макета. Макет использует демоданные; рабочая сборка обращается только к Django своего сервера и не подставляет демоданные при ошибке.

## Что изменилось

- Светлая/тёмная тема, профиль с действующей ролью, боковое меню и свайп слева.
- Объекты раскрываются: улица → дом → лифты. Исходные адреса при миграции сохраняются. Если адрес нельзя надёжно разобрать, он попадает в группу без указанной улицы.
- График на 1–366 дней: сутки/день/ночь/своя длительность, очередь механиков, повтор через N дней, предварительный просмотр, проверка пересечений и изменений другим пользователем. Отсутствие дежурства не обозначает выходной.
- Результат ремонта, до 8 фото на заявку. Сервер проверяет изображения, убирает EXIF, хранит в отдельном постоянном томе; доступ только после входа в организацию.
- Запчасти: дом из справочника → лифт → деталь/количество; механику доступна своя новая заявка, руководителю — изменение статуса.
- Общий чат: последние 200 сообщений, обновление каждые 5 секунд. Переписка сохраняется целиком; CSV за период выгружает только роль ADMIN или superuser. DIRECTOR этого права не получает.
- Общая библиотека PDF, автоматический подбор в карточке лифта. Журнал ТО и ремонта с периодом и рабочей печатной выгрузкой. Юридически значимая электронная форма и подписи пока не реализованы.
- Роли и изоляция организаций, CSRF, аудит операций без текстов переписки/паролей, диагностические логи текущего сеанса.

## Что требуется от Сергея сейчас

1. Скачать приватный артефакт `LiftControl-v0.4-amd64` из успешно завершившейся GitHub Actions сборки нужного коммита, распаковать и передать файлы на VPS в отдельную папку, например `/home/liftadmin/update-v04`.
2. В этой папке выполнить:

```bash
sudo bash update-v04.sh
```

Скрипт предназначен для уже настроенного `/opt/liftcontrol`: существующие Compose, PostgreSQL 18, секреты и SSH-туннель. Он проверяет SHA256, сохраняет предыдущий образ и резервную копию базы, применяет миграции, запускает новую версию и проверяет возможность записи фото. При ошибке запуска пробует вернуть старый образ. Ключи, пароли, порт PostgreSQL и исходный Compose не переписываются. API остаётся на `127.0.0.1:18080`.

3. Войти прежним superuser. Для сотрудников в `/admin/` создать пользователей и Membership: организация, роль и привязка к механику. `is_staff` сам по себе больше не предоставляет доступ к данным. Пароль выдавать отдельно; не присылать его в чат. Демоданные в рабочую базу не добавляются.
4. Проверить свою заявку, фото, график и запрос запчасти. При ошибке скачать диагностические логи в настройках.

## Последующие запуски и резервирование

```bash
cd /opt/liftcontrol
sudo docker compose -f compose.yaml -f compose.api.yaml -f compose.v04.yaml ps
sudo docker compose -f compose.yaml -f compose.api.yaml -f compose.v04.yaml logs --tail=80 api
```

Вложения находятся в `liftcontrol_private_media`. Ежедневная резервная копия базы без этого тома не сохраняет фотографии и PDF. Нужно добавить резервирование обоих хранилищ, шифрованную внешнюю копию и контроль восстановления. Не выполняйте `docker compose down -v`.

Миграция расширяет схему. Добавленные поля старых таблиц имеют значения по умолчанию в БД, чтобы предыдущий образ мог работать при откате. Новые записи чата/запчастей/фото при откате не удаляются, но не видны старой версии. Не откатывайте миграцию и не восстанавливайте старый дамп поверх новых записей без отдельного решения.

## Следующий этап проекта

Проверить на реальных данных роли и назначение сотрудников; выбрать домен для доступа с телефона. До публичного запуска потребуются HTTPS, ограничение попыток входа на прокси, резервирование с восстановлением, политика хранения переписки/фото и контроль серверных ресурсов. Этот пакет не открывает VPS в интернет и не заменяет эти настройки.

## Проверка разработки

Автотесты проверяют изоляцию организаций, серверные ограничения экспорта, подмену автора, права механика, CSRF, фото и их лимиты, завершение ремонта, планирование через границу года, устаревший предпросмотр и сохранение смен за границей периода. CI отдельно проверяет PostgreSQL, роль базы без административных прав, сборку React и Docker. Установка на реальный VPS требует проверки после выполнения скрипта: у текущей сессии нет его SSH-ключа.
