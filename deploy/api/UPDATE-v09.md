# LiftControl 0.9 / Android 0.4.0 beta

## Что требуется сейчас

1. Распаковать серверный архив `LiftControl-v0.9-amd64.zip` в отдельный каталог и выполнить `sudo bash update-panel.sh`. Сценарий проверит контрольные суммы, сохранит предыдущие образы и резервную копию БД, применит миграцию 0009 и проверит API 0.9. Рабочие данные сохраняются.
2. Проверить Web 0.9 внизу панели и `offline_sync_api: 1` в `/api/health/`.
3. Установить подписанный APK `LiftControl-Android-0.4.0-beta-arm64.apk` поверх текущего приложения. Не удалять прежнее приложение: удаление Android стирает локальную базу. Подпись должна совпадать с сохранённым сертификатом.
4. Один раз войти при наличии связи и обновить данные каждой организации. Это нужно для сохранения адресов, лифтов, сотрудников, смены и разрешения на создание во время офлайн-дежурства.

## Исправления

- Зашифрованная SQLite-база в закрытом каталоге приложения. Кэш и черновики предыдущей версии переносятся автоматически. Текст, фото, credentials для фоновой синхронизации и ответы сервера защищены AES-256-GCM с ключом Android Keystore. Резервное копирование приложения отключено.
- Создание/принятие/завершение/остановка/продолжение/назначение и отмена заявок, комментарии и фото записываются до отправки. Подтверждение на экране появляется только после успешной записи на телефон. Очередь видна вверху; ошибки остаются для проверки и копирования.
- Фоновая отправка через Android JobScheduler при наличии сети, повтор при открытии/возврате приложения и обновлении экрана. Android может откладывать фоновые задания из-за энергосбережения; после принудительной остановки приложения нужно открыть его. Для срочного застревания при отсутствии связи необходимо отдельно связаться с диспетчером: сохранение на телефоне не означает доставку.
- UUID операции и серверная квитанция в одной транзакции: потеря ответа и повторная отправка не создают повторные заявки, фото, комментарии или события. Проверяются текущая организация, доступ, исполнитель и допустимый переход статуса. Неотправленные данные не стираются при истечении входа; повторный вход тем же аккаунтом восстанавливает очередь.
- Если заявка записана во время офлайн-дежурства и связь появилась после передачи смены, проверяется ограниченное подписанное сервером разрешение, время записи и историческая смена. Произвольно заявленные телефоном права не принимаются. Операции старше 7 дней требуют проверки; они остаются на телефоне.
- Исполнитель по умолчанию — действующий закреплённый механик. Диспетчер, дежурный и администратор выбирают другого механика. Переназначение новой заявки требует причины и сохраняется в истории.
- В выборе лифта показаны подъезд, модель, грузоподъёмность и учётный/заводской номера при наличии данных. Несколько лифтов одного дома отмечаются вместе; по каждому создаётся своя заявка с независимым результатом ремонта. Недостающие сведения можно заполнить в карточке лифта.
- Чат доступен в шапке Android. В общей библиотеке администратор/руководитель может удалить документ с причиной: файл и ревизии сохраняются, документ исключается из списка и автоподбора. Ручные документы в карточках лифтов не добавляются.
- Логи тестовой версии фиксируют этапы очереди и коды ошибок без тела заявок, фото, паролей и ключей.

## Проверка после установки

1. На тестовом аккаунте обновить данные, отключить интернет, создать заявку и добавить комментарий/фото к принятой заявке. Проверить «Сохранено на телефоне / ожидает отправки».
2. Закрыть и открыть приложение без связи. Записи должны оставаться в списке и очереди.
3. Включить интернет. Дождаться фоновой отправки или открыть приложение. Проверить заявки с другого устройства, отсутствие дублей и пустую очередь после обновления.
4. Повторить с другой организацией: записи и права не должны смешиваться. Проверить выбранного исполнителя, два лифта по адресу и удаление документа.

## Что требуется глобально

Для рассылки сотрудникам — постоянный защищённый ключ APK, HTTPS и внешние резервные копии VPS. Для реальных push остаётся однократная настройка Firebase; SQLite и синхронизация не зависят от FCM. Система не требует новых открытых портов. Чат, ТО, личные задания и редактирование справочников в этом выпуске требуют связи.

Техническая основа: [SQLiteOpenHelper](https://developer.android.com/reference/android/database/sqlite/SQLiteOpenHelper), [Android Keystore](https://developer.android.com/privacy-and-security/keystore), [JobScheduler](https://developer.android.com/reference/android/app/job/JobScheduler), [каналы Flutter](https://docs.flutter.dev/platform-integration/platform-channels).
