# LiftControl 0.7 — замечания с телефона

## Установка на существующий сервер

Скачать ZIP **LiftControl-v0.7-amd64**, распаковать и выполнить в его папке:

```bash
sudo bash update-panel.sh
```

Нужна установленная версия 0.6 с Android API. Обновление проверяет контрольные суммы, сохраняет pg_dump, ставит только новые миграции, проверяет API 0.7 и перезапускает прежние push workers. При ошибке возвращает старый образ. Новые столбцы имеют совместимые значения по умолчанию для отката. Данные из таблиц не импортируются. Контейнер панели не получает Docker socket или ключей SSH. Внутренний тег образа `liftcontrol-api:0.6` сохранён для совместимости существующих Compose-файлов; версия приложения — 0.7.

## Последующие обновления Android

Каталог `/opt/liftcontrol/updates` монтируется в API только для чтения. Публикует файлы администратор на сервере. Скрипт копирует APK под неизменяемым именем, считает SHA-256 и атомарно обновляет `release.json`.

Скачать APK из **Android APK and device tests**, распаковать рядом файл `android-release.json`. Реальный `version_code` берётся из этого JSON, а не из номера версии на экране. Пример:

```bash
sudo python3 publish-update.py LiftControl-Android-0.2.0-beta-arm64.apk --kind android --version 0.2.0-beta --version-code 2010 --notes 'Сотрудники, остановки лифта и обновления'
```

Заменить `2010` на `version_code` своей сборки. В приложении: **Профиль → Обновления → Проверить обновления → Скачать и установить**. Проверка также выполняется при старте/возврате в приложение, не чаще раза в 12 часов. Проверяются HTTPS того же сервера, размер, SHA-256, идентификатор пакета, более высокий versionCode и совпадение сертификата. Установку подтверждает стандартный установщик Android. Если подпись beta изменилась из-за утраты CI-кэша, автообновление будет отклонено; нужен постоянный закрытый ключ подписи для коммерческого выпуска.

Для серверного пакета:

```bash
sudo python3 publish-update.py LiftControl-v0.7-amd64.zip --kind panel --version 0.7 --notes 'Обновление панели и API'
```

Веб-панель показывает пакет и даёт скачать его администратору. Установка серверного кода выполняется владельцем через `update-panel.sh` по SSH. Нельзя безопасно давать веб-процессу право исполнять произвольные загруженные ZIP от root. SHA-256 проверяет целостность, не автора пакета: публикуйте только пакет проверенного GitHub Actions проекта. Доступ к публикации — через SSH; публичной загрузки пакетов в приложении нет.

## Системные уведомления Android

Подготовлен FCM HTTP v1; без настройки проекта Firebase доставка не заявляется работающей. Публичные параметры выдаёт наш авторизованный API. Закрытый ключ монтируется только в отдельный worker. Через Google передаются номера события/заявки/организации и состояние; адреса, ФИО, тексты и фото не передаются. В базу добавлена очередь с повторами, проверкой текущего состояния, сеанса, смены пароля и отзыва доступа. Телефон подавляет повторные и пришедшие не по порядку события, использует системный канал со звуком. Нажатие открывает организацию и заявку с проверкой доступа.

Однократно владельцу нужно:

1. Создать проект в [Firebase](https://console.firebase.google.com/), зарегистрировать Android пакет **ru.liftcontrol.app.beta**, скачать `google-services.json`. Analytics для приложения не включать.
2. Включить **Firebase Cloud Messaging API v1**. Создать ключ сервисного аккаунта с правом отправки FCM. Хранить JSON ключа закрытым, не отправлять его в чат/репозиторий.
3. Загрузить оба JSON в закрытую папку сервера и из папки релиза выполнить:

```bash
sudo python3 configure-fcm.py /root/firebase/google-services.json /root/firebase/service-account.json
sudo bash update-panel.sh
```

4. В новом APK открыть **Профиль → Системные уведомления → Включить**, разрешить уведомления Android. Кнопка **Проверить звук** — локальная проверка канала; реальную доставку проверять новой заявкой при погашенном экране на целевом Samsung. Проверить также принятие, остановку и завершение, отсутствие повторной «новой заявки» после завершения. Принудительная остановка приложения системной кнопкой «Остановить» требует последующего запуска; Samsung может дополнительно ограничивать фон.

Основание реализации: [FCM Android](https://firebase.google.com/docs/cloud-messaging/android/get-started), [получение сообщений](https://firebase.google.com/docs/cloud-messaging/android/receive-messages), [HTTP v1](https://firebase.google.com/docs/cloud-messaging/send/v1-api).

## Что проверить владельцу сейчас

- Установить серверный пакет 0.7 и APK 0.2.0 beta, войти администратором.
- Создать сотрудника в Android, войти им на другом устройстве; проверить список механиков и выбор при назначении.
- Принять заявку, отметить остановку с причиной, проверить карточку лифта, продолжить и завершить ремонт.
- Проверить график с прошлой датой, поиск адреса и формы на складном Samsung.
- При сбое отправить диагностический отчёт. Пароли, bearer/FCM токены и содержимое заявок в него не включаются.

Для коммерческого выпуска глобально остаются постоянная подпись APK, выбранный постоянный домен HTTPS, резервное копирование вне VPS и проверка доставки FCM на рабочих телефонах. Наличие кода уведомлений не является результатом такой проверки.
