# LiftControl 0.6 — дежурство и две организации

Это обновление рабочей Django/React версии 0.5. Оформление сохранено. Код находится в приватном репозитории.

## Что меняется

- Дежурный получает права автоматически по времени смены. По умолчанию сутки начинаются в 09:00 по часовому поясу организации (Благовещенск, UTC+9). Интервал включает начало и исключает окончание. В 08:59 действует предыдущая смена; в 09:00 — следующая. Если следующая смена не назначена, права не продлеваются: заявки создаёт диспетчер/руководитель.
- «Принял смену» подтверждает выход на связь. Эта отметка не задерживает автоматическую выдачу прав.
- Назначенный механик или диспетчер запрашивает подмену с причиной. Выбранный сменщик подтверждает её под своим аккаунтом. До подтверждения права остаются у исходного дежурного. Для текущей смены сохраняются оба участка времени; будущая смена передаётся целиком. Операции записываются в журнал.
- В одной организации в каждый момент один дежурный. Начавшиеся смены не удаляются и не переписываются через редактор.
- У одного пользователя несколько членств: собственные роль и карточка сотрудника в каждой компании. В интерфейсе можно переключать компании. Заявки, фото, чат, документы, график, сотрудники и запчасти проверяются сервером по выбранной компании. Заголовок организации защищает открытые вкладки от смешивания контекста.
- Добавление компании: Настройки → Добавить организацию. Создатель становится администратором новой пустой компании. Директор/администратор выдаёт одноразовое приглашение на 7 дней с ролью и выбранной карточкой механика. Совместитель вводит код под своим существующим аккаунтом. Отзыв доступа к одной компании сохраняет другую.
- Учётные записи создаются существующим администратором в Django; общедоступной регистрации нет. Связывать человека с карточкой по догадке о фамилии система не будет.
- Системные уведомления идут через Service Worker. Настройка показывает фактический статус и содержит отдельную проверку уведомления телефона. Отправитель push запускается отдельно. Один телефон получает заявки всех компаний, где пользователь — действующий механик; доступ перепроверяется перед отправкой.
- Диагностические логи сохранены. В них нет кодов приглашений, паролей, текста сообщений и push-ключей.

## Замена пилотных данных

При первом запуске установщик сохраняет PostgreSQL, вложения и дополнительный JSON-снимок базы, затем удаляет пилотные объекты, лифты, заявки/фото/комментарии, ТО, графики, чат, запчасти и документы. Аккаунты, их пароли, организации, членства, связанные карточки сотрудников и журнал аудита сохраняются. Не связанные с аккаунтами или приглашениями старые карточки сотрудников удаляются.

Загружается фото листа «Лифты» из «График дежурств 2022.xlsx»: **157 единиц в 57 адресных карточках**, только в «Мегаполис».

| Ответственный из таблицы | Единиц |
|---|---:|
| Кантемиров И. | 36 |
| Андросов А. | 40 |
| Николаи А. | 41 |
| Шатравка В. | 40 |
| Всего | 157 |

В числе 157 одна строка обозначена как подъёмник. Колонка «Заочный В.» содержит нулевой итог и не добавляет оборудования. Ленина 178/2 объединён в одну адресную карточку с отдельными лифтом и подъёмником.

Заводские номера, подъезды и число остановок **не указаны**: они остаются пустыми. «МГП-001» и подобные — явно подписанные внутренние учётные номера, их не выдают за заводские. Этажность из таблицы хранится отдельным полем. Тип оборудования, кроме явно указанного подъёмника, не уточнён.

Нужно проверить строку «дубровски» без дома, «Пограничный 5», «Игнатьевское 13» и «Игнатьевское 25/19». Сокращения «50 лет» приведены к «50 лет Октября». Пропуски этажности отмечены в примечаниях. Полная транскрипция с привязкой к строкам: `backend/core/megapolis_data.py`.

Существующие аккаунты механиков сохраняют прежние связи. После обновления выдайте каждому приглашение в Мегаполис с нужной карточкой из таблицы. Прежний администратор/директор получает доступ к Мегаполису; обычные механики автоматически туда не включаются.

Однократный маркер импорта блокирует повторную очистку. Повторная установка 0.6 не стирает новые рабочие записи.

## Установка

Скачайте **LiftControl-v0.6-amd64** из успешного запуска workflow «Build downloadable LiftControl API image» ветки `feature/organizations-duty-v06`. Распакуйте ZIP на сервере, например в `/home/liftadmin/update-v06/`. Проверьте `SOURCE_COMMIT.txt`, затем:

```bash
cd /home/liftadmin/update-v06
sha256sum -c RELEASE.sha256
sudo bash update-v06.sh
```

Нужна установленная 0.4 или 0.5 в `/opt/liftcontrol`. Публичные порты не открываются. Перед изменениями останавливаются API и обнаруженный отправитель push этого проекта. При сбое после начала изменений установщик восстанавливает проверенный полный снимок PostgreSQL, затем запускает прежний образ. При неудаче восстановления API остаётся остановленным, выводится путь копии. Не запускайте два установщика одновременно.

## Уведомления телефона

Внутренний баннер и системный push — разные механизмы. После обновления сначала нажмите Настройки → Проверить системное уведомление: оно проверяет разрешения браузера/Android, не серверную доставку.

Для постоянной эксплуатации нужен доступный сотрудникам HTTPS-адрес. Домен необязателен: новое дополнение PUBLIC-HTTPS.md настраивает доверенный сертификат прямо для IP VPS. Приватный SSH-туннель с `127.0.0.1` пригоден для испытания, для открытия заявок через него нужно активное подключение; на каждом устройстве отдельная подписка. В полном архиве есть install-v06-with-https.sh: он объединяет обновление с настройкой публичного HTTPS по IP или домену; подробности — PUBLIC-HTTPS.md.

После настройки адреса на сервере из распакованного обновления:

```bash
sudo bash configure-push.sh https://YOUR-LIFTCONTROL-HOST
```

Адрес должен быть вашим реальным HTTPS-адресом системы. Он используется как VAPID subject; скрипт не настраивает DNS, сертификат и reverse proxy. Закрытый ключ генерируется на VPS, выдаётся только отправителю, не выводится в терминал. Повторная генерация блокируется, чтобы не потерять подписки. После запуска на каждом телефоне: Настройки → Включить push. Проверьте новую заявку при свёрнутом браузере.

Параметры уведомления запрашивают обычный звук и вибрацию. Сам звук/громкость определяет ОС: включите разрешения Chrome/браузера и звук соответствующей категории уведомлений, проверьте режим «Не беспокоить». Веб-приложение не может принудительно обойти эти настройки.

Документация механизма: https://www.w3.org/TR/push-api/ и https://notifications.spec.whatwg.org/ .

## Что потребуется от Сергея

1. На этом этапе — перенести готовый архив на VPS и запустить установщик; прямого SSH-доступа из среды разработки нет.
2. После установки — связать реальные аккаунты с четырьмя карточками Мегаполиса через приглашения, уточнить спорные адреса и составить график.
3. Перед работой команды — применить настройку HTTPS (можно по текущему IP), запустить отправитель push и проверить доставку/звук на телефонах.
4. В процессе эксплуатации — заполнять заводские номера, подъезды и реальные остановки по паспортам, проверять график и подмены.
