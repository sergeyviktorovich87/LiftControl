# Как раздать обновление Android сотрудникам

## От администратора сейчас

После установки панели 0.9 загрузите `LiftControl-Android-update.zip` на сервер. В папке с архивом выполните:

```bash
unzip -o LiftControl-Android-update.zip
sudo bash LiftControl-Android-update/publish-android.sh
```

Сценарий проверяет размер и SHA-256 APK по данным сборки, готовит каталог обновлений и публикует версию. При первом подключении каталога возможен короткий перезапуск API. При следующих публикациях уже подключённый API не перезапускается. База лифтов и заявок не меняется. Веб-процесс имеет только чтение каталога; публикация требует административного доступа к серверу.

Папка `/opt/liftcontrol/updates` обслуживается через защищённый API. Недостаточно просто скопировать в неё APK: нужен правильный `release.json`, который сценарий создаёт автоматически. Метаданные сборки и versionCode вручную не редактировать.

## Что увидит сотрудник

1. Приложение проверяет опубликованную версию при входе и возврате на экран приложения. Автоматическая проверка ограничена интервалом 12 часов; опубликованная версия появляется у людей при следующей проверке, а не мгновенно у всех.
2. На главном экране появляется предложение обновиться. Нажатие открывает настройки; в разделе «Обновления» есть кнопка «Скачать и установить».
3. Телефон скачивает APK с этого же сервера, проверяет размер, SHA-256, имя приложения, более высокий versionCode и ту же подпись.
4. Android показывает подтверждение установки. Если попросит разрешить установку из LiftControl, сотрудник разрешает её и повторяет «Скачать и установить».

Чтобы обновиться сразу: **Профиль и настройки → Обновления → Проверить обновления → Скачать и установить**. Интернет нужен для загрузки APK. Приложение удалять не нужно: учётная запись, настройки и локальная очередь остаются при обычном обновлении поверх установленной версии.

В этом пакете опубликована проверенная Android 0.4.0, сборка 2030. Если телефон уже на сборке 2030, предложение обновления не появится — это нормально. На версиях 0.3 и 0.4 механизм уже есть. Более старый APK без встроенного обновления нужно заменить вручную один раз.

## Следующие выпуски

Для каждой новой версии используется такой же пакет и те же две команды. Новый каталог заменяется атомарно после копирования APK. Старые файлы не удаляются. Более низкий versionCode и другой APK с уже опубликованным номером блокируются; повторная публикация того же файла допустима.

Сборщик подготавливает этот пакет из проверенного архива CI командой `python deploy/api/package-android-update.py ПУТЬ_К_АРХИВУ_СБОРКИ --output LiftControl-Android-update.zip`. В него автоматически входят APK, исходные метаданные, сценарии публикации и контрольные суммы. Администратору сервера не нужно самостоятельно составлять JSON.

Один опубликованный APK доступен всем авторизованным сотрудникам организаций на этом сервере. Не нужно отправлять каждому ссылку. FCM для этого механизма не требуется. Пока приложение закрыто и не проверяет сервер, немедленное уведомление не гарантируется.

## Что требуется постоянно

Нужны HTTPS, сохранённый ключ подписи и растущий versionCode. Закрытый ключ подписи хранится у сборщика, а не в папке обновлений на VPS. Пароль или токен сотрудника в APK не встраивается. Автоматическая публикация не означает скрытую установку без подтверждения Android. Не следует делать обновление обязательным, пока на телефоне есть неотправленные данные.

Сценарии публикации пишут этапы и ошибки в терминал без паролей и содержимого заявок. Перед изменением подключения каталога создаётся резервная папка в `/opt/liftcontrol/backups/apk-publication-*`.
