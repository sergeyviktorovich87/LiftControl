# Обновление Android из серверной папки

Выпуск рассчитан на пакет Android `ru.liftcontrol.app.beta`. Для обновления поверх предыдущего APK нужны прежний сертификат и более высокий versionCode. Сборка и проверка подписи описаны в [инструкции для GitHub](../../docs/ANDROID_SIGNING.md).

## Публикация через Server Box

1. Откройте `/opt/liftcontrol/updates/android/`. Папку создаёт установщик панели. Если её нет, сначала уточните установленную версию через `/api/health/`.
2. Загрузите подписанный APK с временным окончанием `.part`. После завершения переноса переименуйте его так, чтобы имя оканчивалось на `.apk`. Например, `LiftControl-Android-0.13.5-beta-arm64.apk`.
3. На тестовом телефоне откройте приложение. При обнаружении более новой версии появится окно с кнопками «Обновить» и «Позже». Первую установку из приложения может потребоваться разрешить в системных настройках Android.
4. Проверьте номер в разделе «Профиль и настройки → Версия ПО», вход, данные и отправку ранее сохранённой очереди. Накатывайте APK поверх прежней установки, чтобы сохранить данные.

Обнаружение APK при открытии работает без Firebase. При настроенном FCM поддерживающее этот тип уведомления приложение дополнительно получает Push о новой версии.

## Публикация с описанием изменений

Архив подписанной сборки содержит APK, метаданные и контрольные суммы. Подготовить комплект для сервера можно командой:

```bash
python3 deploy/api/package-android-update.py ПУТЬ_К_АРХИВУ_СБОРКИ --output LiftControl-Android-update.zip
```

На сервере:

```bash
unzip LiftControl-Android-update.zip
sudo bash LiftControl-Android-update/publish-android.sh
```

Сценарий проверяет контрольную сумму и публикует каталог атомарно. После первой настройки API монтирует каталог только для чтения. Если подписанная сборка ещё готовится, папку оставляют пустой.
