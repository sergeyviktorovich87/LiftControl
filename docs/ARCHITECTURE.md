# Архитектура LiftControl

## Роли

- Директор/администратор — видит всю организацию и управляет справочниками.
- Диспетчер — создаёт и распределяет заявки, контролирует статусы.
- Инженер — видит историю, ТО и технические данные.
- Механик/наладчик — получает свои задания через Android-клиент.

## Основной поток

```text
Web / Android
     ↓
Django REST API
     ↓
Бизнес-логика LiftControl
     ↓
SQLite (dev) / PostgreSQL (production)
```

## MVP-сущности

- Building — объект/адрес.
- Elevator — лифт и его заводской номер.
- Technician — сотрудник.
- Ticket — заявка/неисправность.
- Maintenance — плановое ТО/ремонт/осмотр.

## Следующие модули

1. Авторизация пользователей и роли.
2. Привязка механика к учётной записи.
3. Геопозиция и карта механиков.
4. Автоматическое распределение заявок.
5. Планировщик ТО-1/ТО-2.
6. История неисправностей каждого лифта.
7. Документы и паспорта.
8. Фото к заявкам и выполненным работам.
9. Push-уведомления.
10. LiftHelper AI как отдельный интеграционный модуль.
