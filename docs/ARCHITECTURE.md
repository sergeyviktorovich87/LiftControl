# Архитектура LiftControl

Django API принимает запросы панели React и Android Flutter. Сервер проверяет членство, роль и выбранную организацию, применяет бизнес-правила и сохраняет результат в PostgreSQL. SQLite используется в локальной разработке и тестах.

| Компонент | Где смотреть |
| --- | --- |
| API, роли, заявки, дежурства и ТО | `backend/core/`, маршруты в `backend/core/urls.py` |
| Веб-панель и браузерные проверки | `web/src/` и `web/tests/` |
| Android, API-клиент и очередь | `mobile/lib/` и `mobile/android/` |
| Compose, HTTPS, обновления и резервирование | [`deploy/`](../deploy/) |
| Текущая сборка и будущие изменения | [Паспорт выпуска](../RELEASE.md) и [план 0.12](RELEASE_PLAN_0.12.md) |

## Рабочие данные

Объект содержит лифты. К лифту привязаны заявки и записи ТО. Дежурства определяют рабочие права на период смены. Сотрудник может состоять в нескольких организациях. Сведения о действиях, сменах и ремонте сохраняются в истории.

Браузер входит через сессию Django и защищает изменения CSRF-токеном. Android использует отзывной сеанс устройства. Право на операцию проверяется на сервере, в том числе при повторной отправке из очереди.

## Медиа и связь

Медиатека хранит оригинал и миниатюру и связывает файл с записями той же организации. Оригиналы открываются через защищённый API. Android держит неотправленные операции и вложения в закрытом хранилище. Сервер сохраняет квитанцию операции для безопасного повтора. Уведомления Android доставляются через FCM при настроенном Firebase. Развитие истории уведомлений и собственного канала описано в плане 0.12.

На VPS NGINX принимает HTTPS, API работает в Docker, база доступна в сети Compose. Команды установки и восстановления собраны в [инструкции 0.11](../deploy/offline/UPDATE.md).
