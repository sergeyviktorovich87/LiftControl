# LiftControl: план релиза 0.13 (предварительно)

**Статус:** отдельный кандидатный выпуск после базовых задач 0.12. Если небольшой готовый элемент можно безопасно включить раньше, это решение фиксируется в PR и приёмке, а не делается молча. Предыдущий план: [0.12](RELEASE_PLAN_0.12.md).

## 1. Модуль «Пусконаладка»: рабочий процесс

- [ ] **LC13-01.** В навигации модуль отображается **только** сотрудникам, которым администратор выдал право в **общей карточке сотрудника**. В самом модуле нет управления ролями.
- [ ] **LC13-02.** Приглашённый внешний наладчик с отдельным логином и временным паролем может иметь интерфейс только «Пусконаладка», «Мой профиль» и «Настройки». Он не обязан числиться механиком.
- [ ] **LC13-03.** Все права и членство проверяет Django API, включая скачивание фото и историю, а не только меню Flutter/React. Разделение по организациям, доступ к нескольким организациям разный.
- [ ] **LC13-04.** Администратор создаёт объекты и лифты напрямую. Наладчик отправляет запрос на добавление; объект/лифт появляется как активный после согласования администратором.
- [ ] **LC13-05.** Архивировать или удалять объект из активного списка может только администратор, с причиной и сохранением истории, платежей, фотографий и работ.
- [ ] **LC13-06.** На одном объекте могут работать несколько наладчиков, каждый назначен на свои лифты. Оба **видят весь общий объект, все его лифты, прогресс и выполненные работы**, но могут добавлять и менять работы **только своих лифтов**.
- [ ] **LC13-07.** Список объектов для наладчика ограничен объектами его участия; администратор видит все объекты своей организации.
- [ ] **LC13-08.** Лифт может ссылаться на существующую карточку эксплуатации или существовать лишь в проекте наладки. Не дублировать заводской номер в рамках объекта без проверки.
- [ ] **LC13-09.** Прогресс наладки по каждому лифту и общий агрегированный прогресс объекта; 100% наладки не означает сдачу/приёмку лифта.
- [ ] **LC13-10.** Ползунок процента меняет только назначенный наладчик. Перед фиксацией обязательно указать «Что сделано». Сохраняются старый/новый %, дата, автор, описание; при снижении % обязателен комментарий. Администратору доступен **только просмотр** процента.
- [ ] **LC13-11.** Конфликт одновременных правок двух пользователей должен быть обнаружен сервером: запрет тихой перезаписи чужого прогресса, аудит и идемпотентность повторного сохранения.
- [ ] **LC13-12.** Наладчик добавляет личный расход с суммой, датой, объектом/лифтом и кнопкой прикрепления фото. После нажатия открывается окно выбора фото и комментария. Чек хранится в медиатеке с защищённым доступом.
- [ ] **LC13-13.** **Личные расходы видит только их автор и администратор**, даже при общем объекте, в чате, статистике, истории, экспорте и через API. Добавляет расход только наладчик, администратор смотрит чек и отмечает возмещение, не переписывая исходную запись.
- [ ] **LC13-14.** Раздельно учитывать стоимость договора с заказчиком, оплату наладчика, личные траты и компенсацию; одно не подменяет другое.
- [ ] **LC13-15.** Потребности: расходные материалы, инструмент, оборудование, отопление, освещение, вода в приямке, доступ, документация, помощь монтажников. Статусы, ответственный, фото и признак «Блокирует наладку».
- [ ] **LC13-16.** Допработы (например, подключение монтажного режима, перенос станции управления): наладчик предлагает по **своему** лифту, видит допработы на общем объекте, администратор согласовывает или отклоняет. Администратор может сразу создать допработу со стоимостью и зафиксировать своё решение.
- [ ] **LC13-17.** Общий чат наладчиков организации и отдельный чат объекта. Видимость чата только участникам и администратору, фото, видео и документы, доступ к архивам. Сообщение в чате **не является юридическим согласованием** допработы.
- [ ] **LC13-18.** Главный экран не должен дублировать выбор объекта: карточка объекта содержит лифты, прогресс, потребности, допработы и сворачиваемую историю событий.
- [ ] **LC13-19.** Доступность и компактный мобильный интерфейс в привычной зелёной стилистике основной панели; режим наладчика без лишних меню. Интерфейс Web и Android развивается одновременно.
- [ ] **LC13-20.** Офлайн: личные расходы, фото, сообщения и выполненные работы сохраняются в зашифрованной очереди и синхронизируются с повторной проверкой назначения. Чужие данные из кэша не появляются после смены организации.
- [ ] **LC13-21.** Неизменяемый журнал согласований, смены прогресса, файлов и ролей. Администратор видит все объекты, прогресс и чеки, не может под видом наладчика переписать его исходные действия.
- [ ] **LC13-22.** Тестировать модель «два наладчика на одном объекте, разные лифты»: общий обзор, свои изменения, **строгая приватность расходов**, запрос нового лифта и допработы, отсутствие обхода через прямой API.

## 2. Печатный журнал технического обслуживания

- [ ] **LC13-23.** Экспорт PDF по предоставленному Excel «Журнал ТО Мегаполис.xlsx», с согласованной обложкой и шестью колонками: №, вид работ, дата, ФИО/должность исполнителя, подпись исполнителя, подпись ответственного лица. Предусмотреть замечания, разрывы страниц, повтор заголовков, печать A4 альбомная.
- [ ] **LC13-24.** Автозаполнение организации, объекта, лифта, заводского номера и записей ТО, выбор периода и предварительный просмотр; проверить форму с действующими нормативными требованиями РФ перед выдачей как официальной.

## 3. Персональное оформление

- [ ] **LC13-25.** Тема светлая, тёмная, автоматическая; дополнительные варианты синяя, графитовая, зелёная, фиолетовая. Персональный выбор с контрастностью текста, одинаковыми статусами и сохранением настроек.

## Приёмка

Не принимать раздел только по красивому макету. На двух Android-учётных записях и в веб-панели проверить общие лифты, собственные действия, запрет чужих расходов и административное согласование. Проверить серверную авторизацию API, офлайн и журналы. На весь модуль нужны реальные тестовые объекты и сотрудники, предоставленные владельцем без рабочих персональных данных.
