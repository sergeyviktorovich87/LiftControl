## Первая очередь

- **Офлайн.** Проверить заявки, статусы, фото и видео после перезапуска и повторного входа. Android показывает, что сохранено на телефоне, что отправлено и что требует действий. Сервер повторно проверяет доступ при приёме операции.
- **Кэш.** Согласовать срок хранения ранее открытых документов, фото и видео. Привязать кэш к серверу, аккаунту и организации. Очистка кэша сохраняет очередь. Доступ к полученным с сервера файлам перепроверяется при восстановлении связи.
- **APK.** Проверить отсутствие обновления, установку поверх старой версии, отказ при другой подписи или неполном файле. Упростить диагностику папки обновлений. Подписку устройств на уведомления проверить отдельно в очереди уведомлений.
- **Дежурства.** Перенести и перепроверить полезные изменения из черновика на текущей базе. Руководитель видит, какие будущие смены заменит повторное планирование, и подтверждает замену. Действующие смены и история подмен сохраняются. [Черновик исправления](https://github.com/sergeyviktorovich87/LiftControl/pull/11)
- **Диагностика.** Связать записи панели, Android и API по идентификатору операции. Добавить тестовые события для сохранения, повторной отправки и отказа. Пароли, токены, текст сообщений и файлы исключаются из выгрузки.

## LiftControl Push

Собственный канал дополняет Google FCM. В черновике есть опрос HTTPS при работающем приложении и подавление дублей. Для фоновой доставки нужна отдельная проверка на Samsung и Honor/Huawei при заблокированном экране и ограничениях батареи. Проверить смену сети, возврат после перезапуска и доставку при включённом и отключённом FCM. Установку на рабочем сервере проводить после проверки совместимой пары API и APK. [Черновик LiftControl Push](https://github.com/sergeyviktorovich87/LiftControl/pull/12)

## Веб-панель

Modern Web Guidance запланирован для аудита React после фиксации 0.11. Перед запуском проверить происхождение, лицензию и конкретную версию пакета. Запускать `legacy-scan` в отдельной среде разработки. Рекомендации по производительности, доступности и поддержке браузеров проверять на реальных экранах с сохранением утверждённого дизайна. Подключение инструмента оформляется отдельным изменением. [Дорожная карта](ROADMAP.md)

## Приёмка

В начале владелец подтверждает работу 0.11 на VPS и телефоне. Для второй очереди понадобятся правила доступа специалиста и пример журнала наладки. Для уведомлений понадобятся реальные телефоны для проверки фоновой доставки. Перед выпуском 0.12 собрать панель и подписанный APK, проверить обновление с копии 0.11 и записать результаты в паспорт выпуска. Задачи, которые не прошли проверку, переносятся в следующую сборку.
