# LiftControl: план релиза 0.12

**Статус:** кандидатный план, утверждение состава выпуска после приёмки 0.11. **База:** исходники 0.11, Android 0.6.0 beta (2061). **Цель Android:** 0.7 (номер уточняется при сборке).  
**Главное правило:** одна функция реализуется и проверяется в Django API, веб-панели и Android одновременно, если функция не относится только к платформе. Сквозные сценарии проходят проверку между клиентами.

Документ служит единым источником требований для чатов, PR и разработчиков. Галочка [x] появляется только после слияния кода и проверки, а не после обсуждения идеи. Подтверждённые артефакты 0.11 находятся в [RELEASE.md](../RELEASE.md). Полноценный модуль «Пусконаладка» и нормативный журнал ТО выделены в [план 0.13](RELEASE_PLAN_0.13.md), чтобы не задерживать критические исправления. Решение о переносе в 0.12 принимается отдельно, после оценки зависимостей и тестов.

## 1. Надёжность и обновления, приоритет P0

- [ ] **LC12-01 · Офлайн-очередь.** Заявки, принятие/статусы, сообщения, фото и видео сохраняются на телефоне до подтверждения сервером; повторная отправка идемпотентна, работает после перезапуска и переавторизации тем же пользователем.
- [ ] **LC12-02 · Наблюдаемость офлайн.** Пользователь видит «На устройстве», «Отправляется», «Синхронизировано», «Требует исправления»; сервер снова проверяет организацию, права и актуальность заявки.
- [ ] **LC12-03 · Кэш скачанных файлов Android.** Фото, миниатюры, PDF, вложения чата, запчастей, наладки, документация и видео повторно открываются с телефона; оригиналы больших видео загружаются по запросу, разрешённые ранее открытые файлы доступны без сети.
- [ ] **LC12-04 · Безопасность кэша.** Разделение по серверу/пользователю/организации, шифрование, лимит 100/500/1024 МБ, вытеснение старых записей, проверка версии файла (ETag/хеш), очистка без удаления неотправленных данных. Отзыв прав применяется при повторной синхронизации; офлайн-содержимое может оставаться доступным до отзыва локального ключа.
- [ ] **LC12-05 · Публикация APK.** Проверенное размещение APK и JSON метаданных в `/opt/liftcontrol/updates/android/`, обновление только при более высоком versionCode, показ описания изменений, проверка SHA-256 и прежней подписи, кнопки «Обновить» и «Позже».
- [ ] **LC12-06 · Обновление устройств.** Приложение проверяет версию при старте; при публикации возможен Push. Установка поверх прежней версии сохраняет очередь. Android не может принудительно установить APK без системного подтверждения пользователя.
- [ ] **LC12-07 · Дежурства.** Исправить многократное редактирование графика без дублей, с подтверждением замены будущих смен, сохранением истории подмен и запретом потери уже начавшихся смен. Черновик: [PR #11](https://github.com/sergeyviktorovich87/LiftControl/pull/11). Переносить на актуальную базу с отдельным тестом.
- [ ] **LC12-08 · Сквозные логи beta.** Корреляционный идентификатор операций Android/API/Web, события сбоя синхронизации, отправки файла, обновления и Push. Без паролей, токенов, личных сообщений и содержимого чеков.
- [ ] **LC12-09 · Резервирование и rollback.** Проверка полного архива БД + файлов, хранение отдельно от VPS, восстановление на стенде, миграции вперёд и безопасный план возврата до выката.

## 2. Права, сотрудники и данные, приоритет P0

- [ ] **LC12-10 · Права по модулям.** Карточка сотрудника в общей админке: назначение разделов только администратором своей организации. Скрытие меню и серверная проверка API. Права не зависят от должности «механик».
- [ ] **LC12-11 · Внешний специалист.** Можно создать учётную запись приглашённого наладчика без записи в штат механиков, выдать временный пароль со сменой при первом входе и разрешить только «Пусконаладку», профиль и настройки. Не выдавать доступ ко всем лифтам организации.
- [ ] **LC12-12 · Две организации.** Разные разрешения, роли и данные пользователя в каждой организации. Отзыв членства закрывает доступ и сеансы; история записей остаётся.
- [ ] **LC12-13 · Удаление сотрудника.** Безопасное исключение из организации без физического удаления истории. Режим «оставить лифты без назначения» и режим выборочной передачи разных лифтов нескольким исполнителям по адресам.
- [ ] **LC12-14 · Аудит и запреты API.** Логи изменений полномочий, переходов статусов, переназначений и одобрений; тесты на попытку доступа к чужой организации, расходам, вложениям и данным при отзыве прав.

## 3. Уведомления, FCM и собственный сервис, приоритет P1

- [ ] **LC12-15 · Центр уведомлений.** Единая серверная история для Android и Web: заявки, застревания, личные задания, сообщения, графики, остановки и системные события, счётчик непрочитанных и фильтры.
- [ ] **LC12-16 · Переход к записи.** Уведомление открывает нужную заявку/чат/задачу только с действующим разрешением.
- [ ] **LC12-17 · Адресная рассылка.** Новая обычная заявка назначенным исполнителям; личный чат адресату; групповой чат его участникам; застревания дежурному и указанным действующим механикам.
- [ ] **LC12-18 · Тревожные события.** Отдельный приоритет и звуковой канал для застреваний, отсутствие обещаний обхода системного «Не беспокоить» Android.
- [ ] **LC12-19 · Статусы доставки.** Различать запись события на сервере, отправку транспорта, подтверждение получения клиентом, прочтение и отдельное действие «Принял заявку». Галочки в сообщениях, аудит по адресатам.
- [ ] **LC12-20 · Настройки Push.** По типам событий, организации, дежурствам, дням недели и тихим часам (например, 09:00–17:00); исключения для аварийных событий с учётом настроек ОС.
- [ ] **LC12-21 · Android-шторка.** Раскрытое уведомление с адресом, лифтом, неисправностью, приоритетом; действия «Открыть» и «Принять». Принятие подтверждает сервер, повторное принятие блокируется атомарно; недоступная сеть не выдаёт ложное «Принято».
- [ ] **LC12-22 · Чат в шторке.** «Ответить» и «Прочитано» через Android remote input / action receiver с проверкой прав. Контент на заблокированном экране скрывается согласно настройкам конфиденциальности.
- [ ] **LC12-23 · Собственный LiftControl Push.** Сервис только **в дополнение** к FCM, с раздельной диагностикой каналов, идентификатором события и подавлением дублей. Текущий [PR #12](https://github.com/sergeyviktorovich87/LiftControl/pull/12) содержит HTTPS polling только при активном приложении: это НЕ гарантированная фоновая доставка.
- [ ] **LC12-24 · Push в фоне.** Отдельно спроектировать доставку без FCM с учётом Doze, экономии батареи и ограничений Android. Проверить Samsung/Honor/Huawei при спящем экране, смене сети и перезапуске. До доказанной надёжности не делать канал единственным для аварий.
- [ ] **LC12-25 · Сводная диагностика Push.** Статус FCM и собственного канала на устройстве, журналы попыток, повторов, TTL событий и безопасное отключение по feature flag.

## 4. Заявки, запчасти, чат и ТО, приоритет P1

- [ ] **LC12-26 · Длительный ремонт.** Отдельный статус заявки с обязательной причиной и необязательной ожидаемой датой; не снимать автоматически независимый признак «Лифт остановлен».
- [ ] **LC12-27 · История карточки.** Сворачиваемая лента событий в заявках, карточках лифтов и заданиях; автор, дата, тип операции; серверные права на детали.
- [ ] **LC12-28 · Подтверждения заявки.** Отдельно показывать отправлено/доставлено/прочитано/принято и историю каждого исполнителя без смешения прочтения с согласием.
- [ ] **LC12-29 · Фото запчастей.** Камера/галерея, несколько фото, крупный просмотр маркировки, комментарий. В заказе с несколькими позициями фото привязывается к конкретной запчасти.
- [ ] **LC12-30 · Редактирование заказа запчастей.** Название, артикул, количество, лифт/объект, описание, фото и состав позиций; автор до согласования, администратор по правилам статуса.
- [ ] **LC12-31 · Контроль согласования запчастей.** Правки существенных полей сбрасывают предыдущее согласование; после заказа поставщику изменения оформляются отдельным исправлением, а не скрытой заменой. Полная история.
- [ ] **LC12-32 · Цитирование в чате.** Из заявки/заказа/позиции запчасти отправка связанной карточки в личный или групповой чат с собственным комментарием; из чата выбор записи.
- [ ] **LC12-33 · Связанные обсуждения.** Переход из чата к исходной заявке/запчасти и обратно к обсуждениям; актуальные статусы и фотографии по разрешению, ссылка не расширяет доступ.
- [ ] **LC12-34 · Согласованность данных.** Смена статуса или удаление/архивирование записи отображаются в обоих клиентах; тесты расхождения локального кэша и сервера.

## 5. Интерфейс и качество, приоритет P2

- [ ] **LC12-35 · Мой профиль.** Личные данные, смена пароля, организации, устройства, уведомления и оформление без копирования рабочего главного экрана.
- [ ] **LC12-36 · Web / Android parity.** Для каждой доработки параллельные экраны и действия в React + Flutter, одинаковые статусы, формулировки и права; платформенные исключения документируются.
- [ ] **LC12-37 · Тестовые сценарии.** Администратор, дежурный, механик, внешний специалист, сотрудник в двух организациях; два телефона и десктоп, работа без сети.
- [ ] **LC12-38 · Modern Web Guidance.** Только после фиксации 0.11: проверить происхождение, лицензию и зафиксированную версию пакета, запускать в изолированной среде, анализировать рекомендации вручную, сохранить утверждённый дизайн.
- [ ] **LC12-39 · Мониторинг версий.** На панели/API/Android отображать версию и совместимость; не путать версию установленного сервера с номером исходного архива.
- [ ] **LC12-40 · Разделение релиза.** Незавершённый крупный функционал перенести в 0.13, не задерживая безопасность и исправления 0.12.

## Что перенесено в 0.13

Полный раздел «Пусконаладка» (включая объекты, наладчиков, прогресс, финансы, согласования, чаты), печатный PDF-журнал ТО по предоставленному Excel, дополнительные цветовые темы. Подробности: [план 0.13](RELEASE_PLAN_0.13.md). Фундамент прав для внешних наладчиков начинается в 0.12, его наличие не означает, что модуль готов.

## Порядок PR и приёмки

1. **Сначала:** 0.11 на реальном VPS и телефоне; Git SHA, архив и подпись; восстановление резервной копии. Не переписывать код 0.11 ради документации.
2. **Затем:** ветка задачи от актуальной стабильной базы. Один PR содержит миграции, API, Web, Android, тесты и записи в CHANGELOG. Для специфичных Android-функций указывается исключение.
3. **Потом:** staging на отдельных данных. Тесты прав, двух организаций, офлайн-синхронизации, файлов, непрерывности Push, совместимости версии, сценарии отката.
4. **Перед выпуском:** проверка контрольных сумм и старого ключа APK, запрет демонстрационного импорта в рабочую БД, обновление `RELEASE.md`.
5. **Владелец:** подтверждает результаты на Samsung и Honor (по возможности), сценарии двух организаций, распределение лифтов; выбирает место и срок внешних резервных копий; разрешает публикацию.

Данные о готовности должны подтверждаться тестом, конкретным коммитом и CI-ссылкой. «Запланировано» нельзя выдавать за «реализовано».
