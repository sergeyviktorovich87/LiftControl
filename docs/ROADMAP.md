### Релиз 0.12 — развитие

**Обязательная детализация:** [план 0.12 с ID и проверками](RELEASE_PLAN_0.12.md). Следующий отдельный кандидат: [0.13, полный модуль наладки и журнал ТО](RELEASE_PLAN_0.13.md). Пункты ниже являются общими ориентирами; полный раздел «Пусконаладка» не считается готовым после внедрения только прав внешних сотрудников.
- [ ] Отдельные разрешения к модулям и доступ приглашённого специалиста только к пусконаладке.
- [ ] Подготовить права, API и безопасную модель доступа для раздела «Пусконаладка»; полный модуль вынесен в кандидат 0.13.
- [ ] Единая схема хранения и кэширования документов, фото и видео с контролем доступа и резервированием.
- [ ] Центр уведомлений и информативные push с безопасным действием «Принять заявку».
- [ ] LiftControl Push как дополнительный канал к FCM. [Черновик](https://github.com/sergeyviktorovich87/LiftControl/pull/12)
- [ ] Редактирование заявок на запчасти, фото и цитирование заявок и запчастей в чате.
- [ ] Использовать Modern Web Guidance для аудита и доработки React-веб-панели: после фиксации 0.11 выполнить `npx modern-web-guidance@latest legacy-scan ./web`, проанализировать результаты и применять только проверенные рекомендации по совместимости браузеров, производительности и доступности. Установка агента: `npx modern-web-guidance@latest install` в изолированной среде разработки, не на рабочем VPS. Изменения не должны ломать утверждённый дизайн.
- [ ] Перед интеграцией рекомендаций Modern Web Guidance проверить источник и версию npm-пакета, дифф, браузерные и регрессионные тесты, а также риски безопасности; отключать телеметрию в соответствии с требованиями проекта.
- [ ] Каждую новую функцию разрабатывать в отдельной ветке, объединять через PR только после проверок.
- [ ] Тестировать 0.12 на отдельном окружении и базе; выпускать лишь проверенный набор функций. Незавершённое переносить в 0.13.
