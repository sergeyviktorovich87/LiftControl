# LiftControl: отдельный публичный репозиторий для бесплатных проверок 0.13

## Решение

Оригинальный `sergeyviktorovich87/LiftControl` остаётся **private**.
Тестовый репозиторий: `sergeyviktorovich87/LiftControl-CI` (**public**).
Он содержит только новую историю Git (с одного коммита), очищенный снимок
исходников Django/Web/Flutter и тестовый workflow. Он не содержит ключей,
реального реестра лифтов, импорта Мегаполис, данных сотрудников, скриптов
публикации, production secrets, реальных серверных настроек и архивов.

**Не давать доступ к рабочему VPS из публичного GitHub Actions.**
Не создавать в публичном репозитории secrets для Android signing, FCM,
SSH, сервера или базы. Артефакты APK также не публиковать.

## Подготовлено

- `tools/public_ci_snapshot.py`: отбирает только `backend/`, `web/`,
  `mobile/`, `tests/`; исключает чувствительные исходные файлы;
  заменяет имена работников, организации и адреса в демонстрационных
  данных; отменяет публикацию при наличии неизвестных секретов, IP
  или оставшихся реальных названий.
- `tools/tests/test_public_ci_snapshot.py`: тесты отсутствия истории,
  исходных реестров, приватных ключей, проверки отказа и замены имён.
- `tools/public_ci_allowlist.json`: явно проверенные 174 исходных файла;
  любые новые пути запрещены до повторного рассмотрения.
- Каждая сборка публичного CI сначала выполняет **verify**: проверку точного
  списка опубликованных файлов и их SHA-256 по манифесту. Django, Web и Android
  не запускаются, если нарушена целостность снимка.
- Публикация в символьную ссылку и копирование каталогов с `.git`
  запрещены; дополнительные реальные названия объектов заменяются на демо.
- При экспорте создаётся единственный
  `.github/workflows/public-ci.yml`: Django и миграции, React build,
  Flutter analyze/test и **только debug-компиляция**.
- У публичного зеркала собственный `README.md`, `.gitignore`,
  манифест файлов и новая история Git. Политика секретов: никогда не
  копировать содержимое `.github/workflows/` приватного проекта.

## Один шаг владельца на GitHub

Откройте https://github.com/new и создайте репозиторий:

- Owner: `sergeyviktorovich87`
- Repository name: `LiftControl-CI`
- Visibility: **Public**
- Не добавлять README, license или .gitignore, оставить пустым.

Затем пришлите адрес
`https://github.com/sergeyviktorovich87/LiftControl-CI`.
Подключение GitHub умеет добавлять файлы в существующий репозиторий,
но не умеет самостоятельно создавать новый.

При необходимости подтвердите доступ GitHub connector к новому
репозиторию. **Не переводите исходный LiftControl в Public.**

## Локальная подготовка для разработчика (альтернатива)

Из отдельного локального клона приватной ветки `feature/release-v013`:

```bash
python3 -m unittest tools.tests.test_public_ci_snapshot -v
python3 tools/public_ci_snapshot.py --source . --output ../LiftControl-CI-export
```

Экспорт не создаёт удалённый репозиторий и не пушит файлы автоматически.
Проверьте содержимое `../LiftControl-CI-export` перед его публикацией.
При публикации из локального Git обязательно инициализируйте **новый**
репозиторий в папке экспорта. Не добавляйте remote приватного проекта,
не используйте `git push --mirror`, `git clone --mirror`, перенос
`.git` или команды публикации исходной истории.

## Сборка и обратная связь

Снимок зеркала соответствует конкретной ревизии 0.13, но обновления
нужно синхронизировать и проверять заново. Результаты CI public-зеркала
не подменяют заключительную проверку подписанной APK и рабочего VPS.

На публичном репозитории стандартные GitHub-hosted runners обычно
используются без списания включённых минут, но это не снимает
ответственности за публикуемый код и не решает вопрос личных ключей.
Для Android-релиза используйте отдельный защищённый процесс в
приватном репозитории с прежним keystore.

**Пока публичный репозиторий не создан и очищенные файлы не залиты,
CI не перезапущен, APK 0.13 не собрана, рабочий сервер не изменён.**
