# LiftControl Android — 0.2.1 beta

Самостоятельный Flutter-клиент к существующему Django API. Код расположен в `mobile/` того же репозитория. Цвета и карточки повторяют веб-версию. На телефоне используется нижнее меню, на широком экране — боковое.

Изменения 0.2.1: переключение работодателя остаётся занятым до завершения чтения защищённого хранилища и обновления API; заголовок сразу показывает выбранную организацию. Запоздалое чтение кэша не может вернуть данные предыдущей организации или завершённого сеанса. Уход приложения в фон во время переключения не стирает ещё не загруженный черновик. Добавлены три проверки этих гонок и события переключения в диагностическом журнале. Сервер 0.7 менять не требуется.

Изменения 0.2.0: создание сотрудников с логином в Android, приглашения и управление доступом; архив сотрудников и лифтов с причиной; состояние «Лифт остановлен» с продолжением ремонта; проверка APK на вашем сервере и установка через Android; поддержка FCM со звуком. Подробная настройка и действия владельца: [UPDATE-v07.md](../deploy/api/UPDATE-v07.md).

## Что работает

- Вход обычным логином и паролем; отдельный отзывной сеанс каждого устройства на 30 дней. Пароль на устройстве не сохраняется. Смена пароля завершает все Android-сеансы.
- Несколько организаций в одном аккаунте, переключение и вступление по коду приглашения. Роли, кэш, черновики и запросы разделены по организации.
- Главная, поиск заявок, фильтры, принятие ответственным механиком, завершение с отчётом, фото из камеры/галереи, комментарии и неизменяемая история. Отмена — только при наличии права и причины; физического удаления нет.
- Улицы → дома → лифты; карточки, история заявок, журнал ТО, автоматически подобранная документация. PDF открывается во внешнем просмотрщике через ограниченный FileProvider; авторизационный ключ ему не передаётся.
- Дежурства, подтверждение приёма смены, согласованная подмена. Руководитель может создать суточный график на период с предпросмотром и чередованием сотрудников. Занятые интервалы сохраняются; сервер проверяет границы смен и права.
- Журнал ТО с результатом, чат бригады, запросы на запчасти, светлая и тёмная темы, управление сеансами, копирование и отправка диагностического отчёта.
- Без сети доступны ранее загруженные списки (кэш до 7 дней) и черновик отчёта по заявке. Черновик хранится зашифрованно, переживает закрытие приложения. Статусы меняются только после ответа сервера. Фото и PDF требуют подключения.
- Демо с явно обозначенными примерными данными, без отправки запросов.

## Подключение к установленному серверу

Для входа требуется сервер с `android_api: 1` в `/api/health/` и миграцией `0006`. Старый API 0.6 без этого дополнения показывает понятное сообщение о необходимости обновления.

Скачайте свежий серверный архив из workflow **Build downloadable LiftControl API image**, распакуйте и выполните **`update-android.sh`**, а не импорт данных из `update-v06.sh`. См. `deploy/api/UPDATE-ANDROID.md`.

В поле «Адрес сервера» указывается только корень: `https://ваш-домен.ru`. Для нынешнего теста через SSH-туннель телефона можно использовать `http://127.0.0.1:18081`, если локальный порт 18081 направлен на серверный `127.0.0.1:18080`. Публичный HTTP, пользовательские сертификаты и обход проверки TLS не допускаются. VPN/SSH не нужны сотрудникам после настройки домена с HTTPS.

Этот выпуск не меняет DNS, firewall и проброс портов. Постоянный адрес пока не зашит в APK.

## Ограничения beta

- Системные уведомления используют FCM HTTP v1 и включаются в профиле после однократной настройки Firebase на сервере. Без этой настройки клиент показывает отсутствие доставки. Локальная кнопка проверки звука не подтверждает доставку с VPS. Проверка экрана в спящем режиме выполняется на рабочем Samsung отдельно. Firebase Analytics не подключён.
- Действия с сервером не ставятся в автоматическую очередь: это предотвращает повторное создание обращений при неопределённом результате. Если запрос оборвался, сначала обновите список и проверьте результат.
- Выход удаляет все локальные данные аккаунта. При отсутствии сети серверный отзыв может потребовать завершения сеанса с другого устройства; приложение сообщает, подтвердил ли сервер выход.
- Администратор и директор управляют сотрудниками из Android и веба. Создание юридической организации пока выполняется в веб-панели. Приглашения позволяют использовать существующий аккаунт для совместительства.
- В этой beta нет фоновой геолокации, полноценного автономного обмена фото и печати нормативного журнала. Неизвестные заводские номера и остановки не выдумываются.

## Что требуется от владельца

**Сейчас:** установить тестовую ARM64 APK на Samsung, обновить сервер подготовленным архивом, указать домен HTTPS либо действующий локальный туннель, войти существующим аккаунтом. На устройстве проверить камеру, галерею, клавиатуру и сон телефона; при проблеме отправить «Профиль → Диагностический отчёт».

**Для выпуска сотрудникам:** выбранный домен и DNS, HTTPS, аккаунты/приглашения и график дежурств; постоянный закрытый ключ подписи; выбранный канал фоновых уведомлений и его конфигурация. Подключение внешнего провайдера уведомлений — отдельная настройка владельца. Для публикации в магазине дополнительно нужен аккаунт разработчика; для установки APK магазин не обязателен.

## Безопасность и диагностика

- API выдаёт случайный bearer-ключ в ответ на проверенный пароль; в базе хранится SHA-256 ключа и привязка к текущему хешу пароля. Сеансы можно отзывать, не завершая остальные устройства. Не более десяти активных устройств.
- Попытки входа ограничены через общую базу, включая несколько процессов Gunicorn. Тела запросов, пароли и ключи в диагностические логи не записываются.
- На Android ключи, кэш и черновики хранятся через flutter_secure_storage. Облачное резервное копирование и перенос данных запрещены настройками приложения. Выбранная организация передаётся в каждом запросе.
- Перенаправления HTTP не выполняются; файлы скачиваются только с того же сервера и из разрешённых защищённых путей. Сертификаты проверяет система, HTTP разрешён только loopback. Права определяет сервер.
- Кольцевой диагностический журнал до 200 событий содержит время, тип события, маршрут с заменой числовых ID, код ответа и длительность. Он сохраняется на телефоне и отправляется только по действию пользователя.
- Новые серверные таблицы только добавляются, существующая веб-авторизация сохранена. Установщик делает проверенный pg_dump и восстанавливает предыдущий образ при ошибке; бизнес-данные не импортирует и не очищает.

## Сборка и проверки

Flutter **3.47.9**, Dart **3.13.7**, Java **17**, Android minSdk **24**. Зависимости фиксируются `pubspec.lock`. Native Android-файлы лежат в `android/`.

```bash
cd mobile
flutter pub get --enforce-lockfile
flutter analyze
flutter test
LIFTCONTROL_BETA=true flutter build apk --release --split-per-abi --target-platform android-arm64
```

Workflow `.github/workflows/android.yml` выполняет анализ, unit/widget-тесты, собирает APK и проверяет подпись; затем эмулятор Android 35 выполняет вход, принятие заявки, загрузку фото, комментарий, завершение, переключение работодателя, карточку лифта, тему и выход с реальным временным Django API. В артефакте теста сохраняются снимки экранов.

Первый переход с ранее выданной 0.1.0 на 0.2 требует однократной переустановки из-за утраченной подписи первой beta. Локальные черновики нужно сохранить заранее; данные сервера остаются. В исправленной сборке используется явно заданный сохранённый ключ и проверка его сертификата перед выдачей APK.

Beta APK имеет отдельный ID `ru.liftcontrol.app.beta` и подписана тестовым ключом, который CI хранит в приватном кэше. Если кэш удалится, подпись новой beta изменится и понадобится переустановка. Постоянный production-ключ нельзя заменять этим механизмом и нельзя коммитить. Он настраивается отдельно в защищённых GitHub Secrets перед распространением сотрудникам.
