# Работа с репозиторием

## Ветки и проверка изменений

`main` хранит стабильную базу. Для каждой задачи создавайте `feature/<тема>` или `fix/<тема>` от актуальной базы. Открывайте PR с описанием результата и проверками. Отдельная общая ветка `develop` не требуется.

Правки API, панели и Android одной функции проверяются вместе. Если функция выпускается на одном клиенте раньше, укажите совместимость и ограничения в PR. Права и правила работы с данными проверяет API.

Перед объединением сверяйте изменения с текущим `main` и проверяйте затронутые сценарии. Изменения базы проверяйте с миграциями и данными предыдущего выпуска. Для Android проверяйте подпись, номер сборки и установку поверх прежней версии. Для интерфейса проверяйте основные экраны на телефоне и компьютере.

## Запись о выполненной работе

- В PR фиксируйте проблему, результат для пользователя, проверки и ограничения.
- В [журнале выпусков](CHANGELOG.md) записывайте изменения, которые попадут в сборку.
- В [паспорте выпуска](RELEASE.md) указывайте версии, исходные коммиты, пакеты, контрольные суммы, порядок установки, миграции и способ восстановления.
- В [журнале репозитория](docs/REPOSITORY_HISTORY.md) фиксируйте решения по веткам и переносам. Перед удалением старой ветки проверяйте её уникальные изменения, открытые PR и пригодность архивной ссылки.

Стабильный выпуск получает тег и карточку GitHub Release с проверенными ZIP и APK. Источники сборок закрепляются по SHA. Серверные секреты, приватные ключи, рабочие базы, вложения сотрудников и сырые журналы хранятся вне Git. Диагностические отчёты для разработки очищаются от секретов и персональных данных.

## Контроль качества PR

Используйте [шаблон PR](.github/PULL_REQUEST_TEMPLATE.md) и связывайте изменение с пунктом из [0.12](docs/RELEASE_PLAN_0.12.md) / [0.13](docs/RELEASE_PLAN_0.13.md). Нельзя считать функцию готовой, если реализована только в панели или только в Android, кроме задокументированного платформенного исключения. Ветка должна стартовать от утверждённой стабильной базы, а миграции и серверные права тестируются независимо от кнопок UI.

**Запрещено:** переносить PR собственного Push в 0.11 без приёмки, генерировать новую подпись для существующего APK, очищать пользовательскую базу тестовым импортом или удалять историю старых веток до проверки. При сбое CI записывайте причину; не подменяйте проверку зелёной отметкой вручную.
